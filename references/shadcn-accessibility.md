# Accessibility patterns

Accessibility should be treated as part of the interface, not a later layer.

## Core rules

- Use semantic HTML for buttons, headings, forms, and tables
- Add visible focus styles
- Make labels and validation errors explicit
- Keep color use from being the only indicator of state
- Ensure keyboard navigation works for dialogs and menus
- Use sufficient contrast ratios for text and controls

## Admin-specific guidance

In stock and order views, accessibility matters because users often scan large tables quickly. Ensure that filters, buttons, and status badges are keyboard-operable and clearly labeled.
